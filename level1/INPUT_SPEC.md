# 土壤湿度自动浇花控制器：Level 1 输入规格（草案）

这份文件说明希望控制器件完成什么功能，是交给 Level 1 设计或器件选型的**输入需求**，不是已经制造出的芯片，也不是器件数据手册。当前产品依据**土壤湿度传感器**判断是否浇水，不按固定时间间隔启动。

## 1. 产品行为

- 读取插在花盆中的土壤湿度传感器。读数达到经过校准的“干燥”条件时，如果水箱有水且没有报告故障，允许启动水泵。
- 每次浇水的最长运行时长由用户设置，默认 **40 秒**。达到设定时长或传感器读数达到“已湿”阈值，**先发生哪个就停泵**。
- 用户可手动取消本次浇水；若水泵正在运行，立即停泵。取消后不得因为土壤仍然干燥就马上重新启动。土壤恢复湿润、之后再次变干，才允许下一次自动浇水。
- 缺水、故障、上电和复位时，水泵保持关闭。运行中出现缺水或故障，也必须停泵，本次不自动重启。
- 不设置“每隔 24 小时”之类的自动启动时间；控制器可以定期**采样**传感器，但采样频率不决定浇水时间。

干燥阈值、已湿阈值、读数增减与湿度的对应关系、传感器采样周期，以及传感器异常的判定条件，要结合真实传感器和花盆测试确定。两个阈值之间留出差距，可减少读数在临界点波动时反复开关泵。

## 2. 控制器边界与信号

| 项目 | 方向 | 含义 |
| --- | --- | --- |
| `clk` | 输入 | 控制器时钟；频率随实际器件确定 |
| `reset` | 输入 | 使控制器回到停泵状态；有效电平随实际器件确定 |
| `moisture` | 输入 | 土壤湿度读数；可能是模拟电压或数字数据，接口随真实传感器确定 |
| `water_ok` | 输入 | `1` 表示水箱有水，`0` 表示缺水 |
| `fault` | 输入 | `1` 表示系统报告故障，`0` 表示未报告故障 |
| `cancel_once` | 输入 | 用户发出一次取消命令；按键去抖和有效电平待接口设计确定 |
| `run_duration` | 配置 | 用户可设置单次最长运行时长，默认 40 秒 |
| `pump_req` | 输出 | `1` 请求水泵驱动器运行，`0` 请求关闭 |

土壤湿度探头可先考虑电容式，以减少暴露金属探针腐蚀的问题；具体型号在 Level 2 选型时确定。有些传感器输出模拟电压，需要 ADC 才能进入数字控制器；有些提供数字接口。若选择现成微控制器，读数、阈值比较、运行时长和取消逻辑可由 Level 3 固件实现；若设计专用数字芯片，则必须明确 ADC 或数字接口与数字逻辑的分界。

旧的 `pump_gate.v` 仅演示“干燥且有水且无故障”这一**瞬时组合条件**。它没有读取真实传感器，也没有实现阈值校准、运行时长、单次取消或防止连续重启，因此不是完整产品控制器。

## 3. 安全和验证要求

| 场景 | 期望的 `pump_req` |
| --- | --- |
| 上电、复位、土壤未达到干燥阈值 | `0` |
| 土壤干燥、水箱有水、无故障、本次未取消 | 允许为 `1`，不超过用户设置的最长时长 |
| 达到“已湿”阈值或最长运行时长 | `0`，不得立刻重复启动 |
| 用户取消本次 | 立即为 `0`，直到土壤先恢复湿润再变干 |
| 缺水或报告故障，包括运行中发生 | `0`，本次不自动重启 |

后续验证至少覆盖阈值附近波动、正常浇水、时长结束、取消、运行中缺水与故障、上电与复位，以及土壤恢复湿润后的下一次变干。

## 4. 交给 Level 2 的实际器件资料

Level 1 的**可用输出**是选定的真实控制器件或已完成的专用芯片资料：型号、数据手册、供电范围、输入电平门限或 ADC 规格、输出驱动能力、上电行为、引脚定义、封装和推荐焊盘。仅有 RTL、仿真结果或逻辑网表，不能直接画出可制造的 PCB。

Level 2 还需确定土壤湿度传感器的真实型号与接口、水位检测方式、用户取消按钮、运行时长设置接口，以及水泵的供电、额定与启动电流。现阶段暂以标称 3.3 V 控制逻辑和 5 V 水泵作为待核对的设计起点；控制器的 `pump_req` 只接水泵驱动电路，不能直接给水泵供电。
